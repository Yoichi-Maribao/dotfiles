# qa-request — QA 依頼を PR 本文のチェックリストにする

**依頼は PR 本文に書く**のが既定（2026-10-20 に Slack 投稿から変更。チェックボックスで進み具合が見え、PR と一緒に残るため）。impl-flow の承認後に QA が必要なときもこのスキルを使う。

Claude には実機やユーザーのアカウントで確認できないこと（実機の見た目・操作感・ストア/外部サービスの画面・課金の実挙動など）を、**ユーザーがそのまま手を動かせる形**で依頼する。

## 1. 依頼の中身を集める

- **出どころ**: 実装サブエージェントの報告、PR の「動作確認」節（自動で確認済みのものは依頼に入れない）、Issue のチェックリスト。
- **確認環境を明記する**: 接続先（本番 API / ローカル）、アプリの起動方法（Expo Go / dev client / シミュレータ等）、必要な事前準備（環境変数、テスト用アカウント、データの投入）。ビルドの作り直しが要る項目は分けて書く。
- **ユーザーにしか分からないことは推測で埋めない**（テスト端末の OS バージョン等）。
- **複数 PR をまとめて最終形で QA する**（スタック PR を順にマージしてから確認する運用など）なら:
  - チェックリストは PR ごとに、その PR の本文に置く（1 か所にまとめない）。
  - 後の PR が同じ画面・挙動を上書きしたら、前の PR の項目を最終形に合わせて書き直すか、「#<後の PR> で確認」として外す。同じ確認を 2 つの PR に重複させない。

## 2. 書式

PR 本文の「実機 QA 依頼」節（無ければ「動作確認」節の後に作る）に、GitHub の Markdown で書く。

```markdown
## 実機 QA 依頼

- 環境: <接続先> / <起動方法>
- 準備: <事前にやること>
- 始める時期: <例: マージして repo ルートで main を pull した後>

### 1. <画面・機能のまとまり 1>

- [ ] 1-1 <操作> → <期待する結果>
- [ ] 1-2 ...

### 2. <まとまり 2>

- [ ] 2-1 ...

NG があれば、番号（例: 2-1）とスクショを PR のコメントで教えてください。
```

- **すべての項目に通し番号を付ける**（まとまりに `1.` `2.`…、項目に `1-1` `1-2`…）。報告を「2-1 が NG」と番号で受け取るため。
- 1 項目 = 1 操作 + 期待結果。「〜が正しく動く」のような曖昧な書き方をしない。
- 項目が多いときは、優先度の高いもの（リリースを止める不具合が出うるもの）を先に並べる。
- チェックはユーザーが付ける。Claude は付けない。

## 3. 書き込む・知らせる

1. 今の本文を取る: `gh pr view <n> --json body -q .body > body.md`。
2. 「実機 QA 依頼」節を足すか置き換える（ほかの節は変えない。ユーザーが付けたチェックを消さない）。
3. `gh pr edit <n> --body-file body.md` で更新する。スクショを添えるときは `--attach`。
4. **QA を始められる状態になったら**（マージ後に pull が要るプロジェクトなら、その後）、チャットで短く知らせる: 対象の PR（複数ならまとめて 1 回）、項目数、所要時間の目安、特に見てほしい所。全文はチャットに貼らない。
5. PR が無い依頼（Issue だけの作業など）は、その Issue の本文かコメントに同じ書式で書く。どちらも無ければチャットに書く。

## 4. 結果を受けたら

- **報告はふつう PR のコメントに来る**（番号 + スクショ）。チェックの付き具合は PR 本文で見る。
- **Slack で来ることもある**（iPhone で操作しているときなど）。ユーザーはその PR について言及するスレッドを作り、その中に NG を列挙する。Slack MCP でスレッドを読み（画像は `slack_read_file`）、内容と画像を `gh pr comment <n> --attach` で PR に転記して、記録を PR 側に残す。転記したら、スレッドに PR のコメントのリンクを返す。
- SSH 越しの作業中などにチャットで来たときも、同じく PR のコメントに転記する。
- 問題の報告は番号から PR を特定し、修正は通常の実装フロー（impl-flow 等）で行う。
- 全項目にチェックが付いたら、プロジェクトのメモリや引き継ぎ資料の「QA 待ち」を消す。
